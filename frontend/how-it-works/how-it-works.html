Architecture & Pipeline

How ShieldAI Protects Every AI Interaction

Operating as an ultra-low latency proxy between client applications and foundational LLMs, ShieldAI guarantees that confidential data never leaves your enterprise perimeter.

01
Inbound Client Prompt

Raw Prompt Ingestion

A user, internal service, or agent passes an AI prompt containing raw names, customer emails, internal API tokens, or health records toward an external LLM.

02
Ephemeral Interception

Firewall Gateway Interception

ShieldAI intercepts the outbound HTTP payload at the network boundary before any external DNS resolution or cloud provider egress occurs.

03
Detection Layer

Multi-Vector Entity Extraction

High-speed regex validators, entropy analyzers, and lightweight Named Entity Recognition (NER) scan for emails, phone numbers, PII, API tokens, and corporate confidential markers.

04
Threat Evaluation

Automated Risk Scoring (0-100)

Detected entities are weighted by severity (e.g. API keys = 90, Names = 20). An aggregate risk score is calculated in <5ms to classify the prompt into Low, Medium, High, or Critical threat tier.

05
Governance Engine

Policy Action Execution

The policy engine enforces organizational rules: Non-critical PII is masked, regulated financial/health data is redacted, and hard credentials cause an immediate prompt block.

06
Prompt Transformer

Sanitized Safe Payload Assembly

The raw prompt is transformed into a clean version replacing sensitive substrings with placeholders (e.g. [NAME_MASKED]), retaining full grammatical and contextual meaning for the LLM.

07
Egress Delivery

Secure Forwarding to Foundation LLM

Only the safe, sanitized prompt is transmitted to OpenAI, Anthropic, Google Gemini, or internal self-hosted LLMs. Zero sensitive enterprise data is exposed or used for training.

ShieldAI Privacy Firewall
